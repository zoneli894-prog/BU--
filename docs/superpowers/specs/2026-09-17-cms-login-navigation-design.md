# BU 后台登录页与官网入口设计

## 背景

BU 官网使用 VitePress 部署到 GitHub Pages，内容后台使用 Decap CMS、Netlify Identity 和 Git Gateway。现有后台已经支持受邀成员使用个人 QQ 邮箱登录，但登录页说明较集中，官网也缺少稳定、易发现的后台入口。

Netlify 免费计划按 credits 计费，构建部署是主要消耗项。本次改动必须把登录页优化和官网导航入口合并为一次发布，并在完成真实登录验证后停用 Netlify 自动构建。

## 目标

1. 在 BU 官网顶部导航栏增加清晰的“后台管理”入口。
2. 将后台登录页改为极简、高效、适合非技术成员使用的单卡片界面。
3. 用常驻三步流程和可折叠常见问题解释首次登录、日常登录及故障处理。
4. 保留现有 Netlify Identity、Decap CMS 和 Git Gateway 的认证与发布链路。
5. 通过一次合并和一次最终部署完成改动，避免不必要的 Netlify credits 消耗。

## 非目标

- 不自建账号密码数据库或后端服务。
- 不在页面中自行收集、保存或处理密码。
- 不更换 Netlify Identity、Decap CMS 或 Git Gateway。
- 不增加公开注册、Google 登录或 GitHub 登录。
- 不修改内容模型、编辑权限或发布流程。
- 不重构官网其他页面的视觉设计。

## 信息架构

### 官网顶部导航

在 `docs/.vitepress/config.mts` 的导航数组末尾新增“后台管理”：

- 位于“2048 小游戏”之后，是桌面端最右侧导航项。
- 指向 `https://curious-brigadeiros-4f1d1a.netlify.app/admin/`。
- 在新标签页打开，并设置 `rel="noopener noreferrer"`。
- 使用 VitePress 现有导航样式；仅沿用主题本身的悬停、焦点和移动端折叠行为，不引入独立导航组件。
- 移动端由 VitePress 自动收入折叠菜单。

### 后台登录页

继续使用 `docs/public/admin/index.html` 作为独立静态登录入口。页面采用单卡片布局：

1. BU 品牌标识。
2. 标题“BU 内容管理后台”。
3. 一句用途说明，明确成员使用受邀邮箱登录，无需 GitHub 或 Google 邮箱。
4. 主操作按钮“登录后台”。
5. 登录和验证状态区域。
6. 默认可见的三步登录流程。
7. 可展开的“登录遇到问题？”常见问题。
8. “返回 BU 官网”文字链接。

桌面端卡片最大宽度约 520px，三步流程横向排列；窄屏下改为纵向排列。页面最小支持 320px 宽度，不出现横向滚动。

## 视觉设计

- 使用 BU 现有深蓝、低饱和金色和米白色，不引入新的主色。
- 页面背景改为米白纯色或极轻微层次，不使用明显渐变。
- 卡片使用细边框和轻阴影，降低当前厚重悬浮感。
- 深蓝色登录按钮是唯一主要操作；金色仅用于标识、步骤编号和轻量强调。
- 保持系统中文字体栈，避免额外字体请求。
- 三步流程在桌面端等宽横排，在移动端纵排并使用细分隔线。
- 常见问题使用原生可展开结构，默认收起，降低初次访问时的信息密度。
- “返回 BU 官网”为次要文字链接，不与主按钮竞争视觉注意力。

## 登录说明文案

默认显示以下三步：

1. 使用受邀的 QQ 邮箱。
2. 首次登录设置密码，之后直接输入密码。
3. 登录成功后进入内容管理系统。

“登录遇到问题？”展开后只说明以下情况：

- 没收到邀请邮件：检查垃圾邮件，或联系网站管理员重新邀请。
- 忘记密码：在登录窗口中使用密码重置入口。
- 提示账号不存在：确认填写的是管理员邀请的邮箱。
- 邮件链接失效：联系网站管理员重新发送。
- 登录成功但后台没有加载：刷新页面；仍失败时联系网站管理员。

说明中不出现 Netlify Identity、Git Gateway 等技术术语，也不公开管理员个人邮箱。

## 交互与数据流

1. 访客从官网顶部导航点击“后台管理”，后台在新标签页打开。
2. 未登录用户看到登录卡片；点击“登录后台”后，调用现有 Netlify Identity 登录窗口。
3. 打开登录窗口期间，主按钮切换为“正在加载…”并暂时禁用，避免重复操作；用户未登录便关闭窗口时，按钮恢复原状。
4. 登录成功后关闭 Identity 窗口、清理地址栏中的认证回调信息，并按现有方式动态加载 Decap CMS。
5. 已登录用户访问后台时，直接加载 Decap CMS，不重复显示登录卡片。
6. 邀请、找回密码、邮箱确认和邮箱变更链接继续由 `invite_token`、`recovery_token`、`confirmation_token` 和 `email_change_token` 自动识别。
7. “返回 BU 官网”指向 `https://zoneli894-prog.github.io/BU--/`。

## 状态与异常处理

- 加载 Identity 或 CMS 时，在 `aria-live` 状态区域显示简短中文状态。
- Identity 脚本未就绪或打开失败时，恢复按钮可用状态，并提示刷新后重试。
- CMS 脚本加载失败时，重新显示登录卡片或错误区域，并给出刷新及联系管理员的建议。
- 认证失败的具体账号提示继续由 Netlify Identity 窗口提供；外层页面不猜测失败原因。
- 邀请或密码恢复回调处理期间显示“正在验证账号信息，请稍候……”。
- 不记录密码、令牌或用户身份信息到本地存储和日志。

## 可访问性与响应式要求

- 登录按钮可通过键盘操作，触控高度不低于 48px。
- 所有交互元素具有清晰的 `:focus-visible` 样式。
- 文本与背景达到可读对比度；状态不只依赖颜色表达。
- 状态区域使用 `aria-live="polite"`，品牌装饰不重复朗读。
- 常见问题优先使用原生 `details`/`summary`，保留键盘和屏幕阅读器语义。
- 尊重 `prefers-reduced-motion`，减少或关闭按钮位移等非必要动效。
- 320px 至桌面宽度均不得出现内容溢出、遮挡或横向滚动。

## 测试与验收

### 自动化检查

- 扩展现有 `tests/admin-login.test.mjs`，检查：
  - 三步登录说明和常见问题文案存在；
  - 登录按钮、状态区域、返回官网链接和原生折叠结构存在；
  - 四类 Identity 回调令牌仍完整；
  - Identity API 地址未被改变；
  - 加载状态和异常处理逻辑存在。
- 新增或扩展配置测试，确认：
  - 顶部导航包含“后台管理”；
  - 地址指向正确的 Netlify `/admin/`；
  - 使用新标签页及安全的 `rel` 属性。
- 运行 Node 测试和 VitePress 完整构建。

### 人工验收

- 桌面端顶部导航最右侧显示“后台管理”。
- 手机端折叠菜单显示同一入口。
- 点击入口在新标签页打开正确后台地址。
- 登录页在桌面端和 320px 窄屏下无溢出、遮挡或横向滚动。
- 三步说明默认可见，常见问题可以展开和收起。
- 受邀成员可以使用 QQ 邮箱和密码登录并进入 Decap CMS。
- 首次邀请、忘记密码和邮箱确认链接能够正确进入相应流程。
- 登录失败、脚本加载失败和加载过程都有可理解的中文反馈。
- “返回 BU 官网”能够返回 GitHub Pages 官网。

## 发布策略

1. 登录页、导航入口及测试在同一功能分支完成。
2. 本地测试和构建全部通过后创建一个 PR。
3. 合并后等待 GitHub Pages 和 Netlify 各完成一次部署。
4. 在生产后台完成一次真实登录验证。
5. 验证成功后停用 Netlify 自动构建；继续保留 Identity 和 Git Gateway 服务。
6. 后续内容发布仍由 Git Gateway 写入 GitHub，并由 GitHub Actions 部署官网，不依赖 Netlify 构建。

## 完成定义

本设计仅在以下条件全部满足时视为完成：导航入口可发现且链接正确；登录页符合上述结构与响应式要求；邀请、恢复和正常登录链路未回归；自动化测试及项目构建通过；生产环境真实登录验证成功；Netlify 自动构建已在验证后停用。
